
Данный документ описывает эндпоинты системы управления производством. API построено на базе **FastAPI** и использует **Swagger** для интерактивного тестирования.

**Базовый URL:** `http://127.0.0.1:8000`

---

## 1. Inventory Management (Складской учет)

Группа методов для работы со справочником ТМЦ и складскими остатками.

### 1.1 Получение списка компонентов

- **Метод:** `GET /components`
    
- **Описание:** Возвращает полный перечень номенклатурных позиций (резисторы, разъемы, платы).
    
- **Ответ (200 OK):** Список объектов `Component`.
    

### 1.2 Оприходование на склад

- **Метод:** `POST /inventory/incoming`
    
- **Параметры:**
    
    - `component_id` (int): ID детали.
        
    - `quantity` (float): Количество для добавления.
        
    - `location` (string): Ячейка хранения (по умолчанию "Warehouse-1").
        
- **Логика:** Увеличивает значение `actual_qty` в таблице `Stock`. Если записи для компонента нет, создает её.

## 2. Production Engineering (Инжиниринг)

Работа с конструкторскими данными и составом изделий.

### 2.1 Получение BOM (Спецификации)

- **Метод:** `GET /products/{product_id}/bom`
    
- **Описание:** Позволяет узнать, из чего состоит готовое изделие.
    
- **Возвращаемые данные:** Список компонентов с указанием позиционных обозначений (например, C1, R5) и количества на одну единицу продукции.
    

---

## 3. Production Control (Управление производством)

Логика планирования и запуска заказов.

### 3.1 Создание заказа

- **Метод:** `POST /orders`
    
- **Описание:** Регистрация намерения выпустить партию продукции.
    
- **Статус по умолчанию:** `New`.
    
- **Ответ (201 Created):** Объект заказа с присвоенным `order_id`.
    

### 3.2 MRP-анализ (Дефицитная ведомость)

- **Метод:** `GET /orders/{order_id}/mrp`
    
- **Описание:** Ключевая функция системы. Сравнивает общую потребность заказа с текущими остатками на складе (`actual_qty`).
    
- **Поле `can_start`:** Возвращает `true`, если всех материалов достаточно для запуска.
    

### 3.3 Запуск производства

- **Метод:** `POST /orders/{order_id}/start`
    
- **Описание:** Переводит заказ в статус `In Progress`.
    
- **Критическое действие:** **Автоматически списывает** материалы со склада.
    
- **Валидация:** Если на складе не хватает хотя бы одной позиции, сервер вернет `400 Bad Request` и списание не произойдет.

## 4. Procurement (Снабжение)

Инструменты для менеджера по закупкам: работа с дефицитом и оформление заказов поставщикам.

### 4.1 Создание закупки (Черновик)

- **Метод:** `POST /procurement/orders`
- **Описание:** Менеджер выбирает «галочками» дефицитные позиции и формирует заказ конкретному поставщику.
- **Параметры (Body):** - `supplier_name` (string): Название поставщика.
    - `items` (list): Список объектов с `component_id` и `quantity`.
- **Логика:** Создает запись `PurchaseOrder` со статусом `Draft`.

### 4.2 Обновление данных о доставке

- **Метод:** `PATCH /procurement/orders/{purchase_id}`
- **Описание:** Ввод логистических данных после оплаты счета.
- **Параметры:** - `tracking_code` (string): Номер отслеживания.
    - `arrival_date` (date): Когда ожидаем детали.
- **Логика:** Переводит заказ в статус `Ordered` или `In Transit`.

### 4.3 Загрузка счета (Документация)

- **Метод:** `POST /procurement/orders/{purchase_id}/upload-invoice`
- **Описание:** Прикрепление файла счета или накладной к заказу.
- **Входные данные:** `file` (UploadFile).
- **Логика:** Сохраняет путь к файлу в поле `invoice_ref`.

### 4.4 Приемка ТМЦ на склад

- **Метод:** `POST /procurement/orders/{purchase_id}/receive`
- **Описание:** Подтверждение фактического прибытия товара.
### 4.4 Приемка ТМЦ на склад  
  
- **Метод:** `POST /procurement/orders/{purchase_id}/receive`  
- **Описание:** Подтверждение фактического прибытия товара.  
- **Логика:** 
			1. Меняет статус закупки на `Received`.  
			2. **Автоматически увеличивает** `actual_qty` в таблице `Stock` для всех позиций из этого заказа.

## Коды ответов

| Код     | Значение    | Описание                                                     |
|---------|-------------|--------------------------------------------------------------|
| **200** | OK          | Запрос выполнен успешно.                                     |
| **201** | Created     | Ресурс (заказ/позиция) успешно создан.                       |
| **400** | Bad Request | Ошибка бизнес-логики (например, запуск заказа при дефиците). |
| **404** | Not Found   | Запрошенный ID (компонент/заказ) не найден в базе.           |
