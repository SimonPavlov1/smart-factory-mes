# Спецификация структуры данных Smart Factory

## 1. Слой моделей: Модуль `inventory.py`

**Назначение:** Управление единым справочником ТМЦ (Товарно-материальных ценностей) и физическими остатками на складах. 

Технические поля в сущности `Component` спроектированы для работы автоматического парсера спецификаций (ПЭ3) и обеспечения возможности поиска функциональных аналогов закупщиком.

| **Сущность**     | **Поле**            | **Тип SQL** | **Ограничения**  | **Описание / Бизнес-логика**                                                      |
|:-----------------|:--------------------|:------------|:-----------------|:----------------------------------------------------------------------------------|
| **Component**    | `id`                | Integer     | PK, Index        | Уникальный системный идентификатор детали.                                        |
| (Справочник ТМЦ) | `name`              | String      | Not Null, Index  | Базовое название типа детали (напр. *Резистор*, *Конденсатор*).                   |
|                  | `part_number`       | String      | Unique, Index    | **MPN**: Артикул производителя. Основной ключ для связи с мировыми базами данных. |
|                  | `category`          | String      | Index            | Группа закупки (напр. *Active*, *Passive*, *Electromechanics*).                   |
|                  | `type`              | String      | -                | Подтип компонента (напр. *Танталовый*, *Шоттки*, *LDO*).                          |
|                  | **`package`**       | String      | Index            | Тип корпуса. Стандартизирует габариты для монтажа (напр. *0603*, *SOT-23*).       |
|                  | **`value`**         | String      | -                | Текстовое представление номинала для UI (напр. *10 кОм*, *4.7 мкФ*).              |
|                  | **`value_numeric`** | Float       | Index            | **Нормализация**: Числовое значение в базовых единицах для фильтрации и поиска.   |
|                  | **`value_unit`**    | String      | -                | Единица измерения номинала (*Ohm*, *uF*, *V*, *H*).                               |
|                  | **`tolerance`**     | String      | -                | Допуск, точность или тип диэлектрика (напр. *1%*, *X7R*, *NP0*).                  |
|                  | **`voltage`**       | Float       | Nullable         | Рабочее напряжение (V). Параметр «строгости» при подборе аналога.                 |
|                  | `unit`              | String      | Default="pcs"    | Единица учета на складе (шт, метр, кг, упаковка).                                 |
|                  | `description`       | Text        | Nullable         | Технические примечания, особенности пайки или хранения.                           |
|                  | `datasheet_path`    | String      | Nullable         | Путь к локальному хранилищу или URL PDF-документации.                             |
| **Stock**        | `id`                | Integer     | PK, Index        | Уникальный ID складской ячейки/записи.                                            |
| (Складской учет) | `component_id`      | Integer     | FK, Unique, Null | Ссылка на **Component**. Заполняется, если на полке лежит покупная деталь.        |
|                  | **`product_id`**    | Integer     | FK, Unique, Null | Ссылка на **ProductType**. Заполняется, если на полке лежит готовый узел/плата.   |
|                  | `actual_qty`        | Float       | Default=0.0      | Текущее физическое количество в наличии.                                          |
|                  | `reserved_qty`      | Float       | Default=0.0      | Количество, заблокированное под активные производственные заказы.                 |
|                  | `min_threshold`     | Float       | Default=0.0      | «Точка заказа»: минимальный остаток для уведомления закупки.                      |
|                  | `location`          | String      | Index            | Адресное хранение: номер стеллажа, полки или ячейки.                              |

### Логические связи (Relationships)
1. **Component ↔ Stock**: Связь "один-к-одному". Каждая уникальная деталь имеет одну запись суммарного остатка (или адресного хранения).
2. **ProductType ↔ Stock**: Связь "один-к-одному". Позволяет учитывать готовые изделия собственного производства на тех же складских мощностях.

## 2. Слой моделей: Модуль `production.py`

**Назначение:** Управление полным жизненным циклом производства: автоматизированный разбор конструкторской документации (ПЭ3), формирование состава изделий (BOM), планирование ресурсов и учет готовых экземпляров продукции.

### 2.1. Интеллектуальный слой (Mapping)
Служит для устранения разрыва между "текстовым" описанием инженера и строгим артикулом склада. Позволяет системе обучаться на основе действий закупщика.

| **Сущность**     | **Поле**       | **Тип SQL** | **Ограничения** | **Описание / Бизнес-логика**                               |
|:-----------------|:---------------|:------------|:----------------|:-----------------------------------------------------------|
| **BOMMapping**   | `id`           | Integer     | PK              | Системный ID связи.                                        |
| (Словарь знаний) | `design_name`  | String      | Unique, Index   | **Ключ**: Текст из файла (напр. "Резистор 0805 10к").      |
|                  | `component_id` | Integer     | FK (Component)  | Ссылка на реальный компонент из `inventory.py`.            |
|                  | `mapping_type` | String      | Default="auto"  | Метка происхождения: `auto` (парсер) или `manual`.         |
|                  | `is_verified`  | Boolean     | Default=False   | Подтверждение технолога (верифицированные связи — эталон). |

### 2.2. Реестр изделий и Состав (BOM)
Описывает структуру производимых продуктов. Поддерживает многоуровневую вложенность (изделие внутри изделия).

| **Сущность**     | **Поле**         | **Тип SQL** | **Ограничения** | **Описание / Бизнес-логика**                          |
|:-----------------|:-----------------|:------------|:----------------|:------------------------------------------------------|
| **ProductType**  | `id`             | Integer     | PK, Index       | Уникальный ID изделия (платы, блока, прибора).        |
| (Реестр изделий) | `name`           | String      | Not Null        | Коммерческое или техническое наименование.            |
|                  | `sku`            | String      | Unique, Index   | Внутренний складской код изделия.                     |
|                  | `drawing_number` | String      | Index, Null     | Децимальный номер чертежа (напр. ЮГИШ...).            |
|                  | `is_subassembly` | Boolean     | Default=False   | Признак узла (полуфабриката), входящего в другие BOM. |
|                  | `revision`       | String      | Default="1.0"   | Версия КД или ревизия печатной платы.                 |
| **ProductBOM**   | `id`             | Integer     | PK              | ID строки спецификации.                               |
| (Спецификация)   | `product_id`     | Integer     | FK              | К какому изделию относится строка.                    |
|                  | `design_name`    | String      | Nullable        | Исходный текст из проекта (для контроля аналогов).    |
|                  | `designators`    | String      | Nullable        | Позиционные обозначения на схеме (R1, C5...).         |
|                  | `resource_id`    | Integer     | Not Null        | ID ресурса (из `Component` или `ProductType`).        |
|                  | `resource_type`  | String      | Not Null        | Дискриминатор: `component` или `product`.             |
|                  | `quantity`       | Float       | Not Null        | Норма расхода на 1 единицу продукции.                 |
|                  | `is_resolved`    | Boolean     | Default=False   | **Статус**: Успешно ли подобрана деталь на складе.    |

### 2.3. Учет производства и экземпляров
Управляет процессом выпуска партий и историей каждого конкретного прибора.

| **Сущность**    | **Поле**        | **Тип SQL** | **Ограничения** | **Описание / Бизнес-логика**                            |
|:----------------|:----------------|:------------|:----------------|:--------------------------------------------------------|
| **Order**       | `id`            | Integer     | PK, Index       | Номер производственного заказа (партии).                |
| (Заказы)        | `product_id`    | Integer     | FK              | Модель изделия, поставленная в план выпуска.            |
|                 | `target_qty`    | Integer     | Not Null        | Количество единиц к производству.                       |
|                 | `status`        | String      | Index           | Статус: `New`, `In Progress`, `Completed`, `Cancelled`. |
|                 | `created_at`    | DateTime    | func.now()      | Штамп времени постановки в план.                        |
| **Reservation** | `id`            | Integer     | PK              | ID записи резервирования.                               |
| (Резервы)       | `order_id`      | Integer     | FK              | Заказ, под который "заморожены" компоненты.             |
|                 | `component_id`  | Integer     | FK              | Конкретная деталь, изъятая из свободного остатка.       |
|                 | `qty`           | Float       | Not Null        | Количество зарезервированного ресурса.                  |
| **Item**        | `id`            | Integer     | PK              | Системный ID физического экземпляра.                    |
| (Экземпляры)    | `order_id`      | Integer     | FK              | Заказ, в рамках которого было собрано устройство.       |
|                 | `serial_number` | String      | Unique, Index   | Уникальный серийный номер изделия (S/N).                |
|                 | `test_result`   | String      | Nullable        | Результат выходного контроля (напр. Pass/Fail).         |

---

### Логические связи (Relationships):
1. **ProductType → ProductBOM**: Каждое изделие имеет древовидный список компонентов.
2. **ProductBOM → Component/ProductType**: Полиморфная связь, позволяющая строке состава ссылаться как на покупную деталь, так и на внутренний узел.
3. **Order → Reservation**: Заказ блокирует компоненты на складе, предотвращая их использование в других проектах.
4. **Order → Item**: Позволяет отследить, из какой партии и в какой день вышел конкретный прибор.
## 3. Слой моделей. Модуль `procurement.py`

Назначение: Управление процессом внешних закупок, логистикой и пополнением дефицита.

| **Сущность**      | **Поле**        | **Тип SQL** | **Ограничения** | **Описание**                                             |
|-------------------|-----------------|-------------|-----------------|----------------------------------------------------------|
| **PurchaseOrder** | `id`            | Integer     | PK, Index       | ID транзакции закупки                                    |
| (Заказ/Счет)      | `supplier_name` | String      | Not Null        | Название (напр. "Чип и Дип" или "КабельТорг")            |
|                   | `status`        | String      | Index           | Статус: `Draft`, `Ordered`, `In Transit`, `Received`     |
|                   | `invoice_ref`   | String      | Nullable        | Номер счета или договора                                 |
|                   | `tracking_code` | String      | Nullable        | Трек-номер для отслеживания ТК                           |
|                   | `arrival_date`  | Date        | Nullable        | Плановая дата прибытия на склад                          |
| **PurchaseItem**  | `id`            | Integer     | PK              | ID строки в заказе                                       |
| (Позиции счета)   | `order_id`      | Integer     | FK              | К какому заказу относится (напр. к заказу в "Чип и Дип") |
|                   | `component_id`  | Integer     | FK              | Какую именно деталь ждем                                 |
|                   | `qty`           | Float       | Not Null        | Сколько заказали                                         |
|                   | `price`         | Float       | Nullable        | Цена за единицу (для учета себестоимости)                |
