# 📘 Шпаргалка по Git для проекта Smart Factory

Краткое руководство по управлению версиями: как сохранять, отправлять и объединять код.

---

## 🚀 Основной цикл работы (Workflow)

Когда ты начинаешь делать новую задачу, придерживайся этого алгоритма:

1. **Создать ветку**: `git checkout -b feature/название-задачи`
2. **Написать код**: (делаешь правки в PyCharm)
3. **Подготовить файлы**: `git add .`
4. **Сохранить (Коммит)**: `git commit -m "тип: описание на русском"`
5. **Отправить в облако**: `git push origin feature/название-задачи`
6. **Слить в Main**: Переключиться на `main`, сделать `merge` и `push`.

---

## 🛠 Основные команды

### 1. Подготовка и проверка
| Команда      | Что делает                                     |
|:-------------|:-----------------------------------------------|
| `git status` | Показывает измененные и новые файлы            |
| `git add .`  | Подготавливает **все** изменения к сохранению  |
| `git diff`   | Показывает конкретные изменения в строках кода |

### 2. Сохранение и отправка
| Команда                   | Что делает                                   |
|:--------------------------|:---------------------------------------------|
| `git commit -m "..."`     | Создает «точку сохранения» с описанием       |
| `git push origin [ветка]` | Отправляет твой код на GitHub                |
| `git pull origin [ветка]` | Скачивает свежий код из облака в твой проект |

### 3. Работа с ветками
| Команда              | Что делает                                   |
|:---------------------|:---------------------------------------------|
| `git branch`         | Список всех веток (текущая помечена `*`)     |
| `git checkout [имя]` | Перейти на другую ветку                      |
| `git merge [имя]`    | Влить изменения из указанной ветки в текущую |

---

## 📝 Правила именования коммитов

Мы пишем коммиты на **русском языке**, используя префиксы для порядка:

* `feat:` — (Feature) Новая функция или логика.
* `fix:` — (Bug fix) Исправление ошибки.
* `docs:` — Изменения в документации (README, MD-файлы).
* `refactor:` — Улучшение структуры кода (без изменения логики).
* `style:` — Правка оформления кода (пробелы, форматирование).

**Пример:** `git commit -m "feat: добавлена схема заказа в app/schemas/order.py"`

## ⚠️ Что делать, если "всё сломалось"?

1. **Отменить `git add`**: `git reset HEAD`
2. **Вернуть файл к состоянию последнего коммита**: `git checkout -- имя_файла`
3. **Посмотреть историю**: `git log --oneline`


| **Атрибут**      | **Тип** | **Обязательность** | **Логика**                                 |
|------------------|---------|--------------------|--------------------------------------------|

| `is_subassembly` | Boolean | Да                 | Флаг для активации рекурсивного обхода BOM |
| `revision`       | String  | Да                 | Контроль версий конструкторской доки       |
