# Правила разработки backend

Общие команды запуска, тестирования и эксплуатации описаны в `smart-factory-ui/docs/DEVELOPMENT.md`.

## Архитектурные границы

- `app/api` принимает запрос, проверяет права и формирует ответ;
- `app/services` содержит бизнес-правила и транзакционные переходы;
- `app/models` описывает хранение данных;
- `app/schemas` валидирует внешние данные;
- `workflow_routes.py` задаёт допустимый маршрут;
- `workflow_service.py` выполняет переходы и создаёт следующие задачи.

## Обязательные инварианты

- одна физическая единица изменяется по `Item.id` или заводскому номеру;
- повтор команды не должен повторно менять остаток;
- количество нельзя проводить без доступных экземпляров или партии;
- ручная корректировка склада всегда создаёт движение;
- ветка одного изделия не блокирует другое изделие того же заказа;
- задача ремонта хранит результат отдельно по каждому устройству;
- после ремонта устройство идёт на повторный тест;
- отмена не удаляет учётные последствия уже выполненных операций.

## Изменение workflow

При добавлении этапа:

1. добавьте тип и роль в `workflow_routes.py`;
2. реализуйте завершение в `workflow_service.py`;
3. добавьте payload формы в API и frontend;
4. добавьте интеграционный тест успешного маршрута;
5. добавьте тест повторной команды и частичной партии;
6. обновите документацию.

## База данных

Структурное изменение выполняется миграцией Alembic. Не редактируйте рабочую SQLite вручную и не коммитьте `.db`, вложения или резервные копии.

## Проверка

```bash
.venv/bin/python -m compileall -q app tests
.venv/bin/python -m unittest discover -s tests -v
git diff --check
```

Все предупреждения ресурсов и deprecated API должны устраняться, а не скрываться фильтром тестов.
