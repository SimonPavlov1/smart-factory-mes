# Правила разработки и стандарты кода

## 1. Контроль версий (Git)
- Все изменения вносятся через тематические коммиты.
- Сообщения коммитов должны начинаться с префикса:
  - `feat:` — новый функционал (например, модель резервирования).
  - `fix:` — исправление багов.
  - `docs:` — изменение документации.

## 2. Работа с базой данных
- Все изменения структуры (таблиц) проводятся через **Alembic миграции**. (Мы их настроим чуть позже).
- Названия таблиц — в нижнем регистре во множественном числе (`components`, `orders`).

## 3. Работа с ветками (Branch Policy)
- **main**: Стабильная версия системы. Прямые пуши разрешены только на этапе инициализации.
- **feature/**: Каждая новая таблица или сервис разрабатывается в отдельной ветке.
- **Интеграция**: Слияние в `main` происходит через Pull Request после проверки работоспособности

## 4. Стандарты Python кода
- Используем **Type Hints** (аннотации типов) во всех функциях.
- Вся бизнес-логика (расчет резервов, создание серийников) выносится в слой `app/services/`. Модели в `app/models/` должны быть "тощими" (только описание полей).

## 5. Документирование PDF-файлов
- Пути к файлам в базе данных хранятся как относительные: `storage/docs/...`.
- Запрещено хранение самих бинарных файлов в Git (они добавлены в `.gitignore`).
