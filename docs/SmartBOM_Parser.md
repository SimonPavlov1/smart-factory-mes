# SmartBOM Parser: Техническая спецификация модуля распознавания компонентов

## 1. Обзор системы
Модуль `bom_parser.py` является ключевым аналитическим узлом системы Smart Factory. Он предназначен для декомпозиции текстовых строк из конструкторской документации (ПЭ3) на структурированные технические параметры.

Основная цель модуля — обеспечить автоматический поиск функциональных аналогов на складе, даже если в файле указан артикул, отсутствующий в базе данных.

## 2. Ключевые возможности
* **Контекстный анализ:** Учет заголовка раздела (например, «Резисторы») для выбора правильного алгоритма парсинга.
* **Нормализация данных:** Автоматический перевод номиналов (кОм, мкФ, нФ) в базовые единицы системы СИ (Ом, Фарад) для числового сравнения.
* **Универсальный поиск корпусов:** Распознавание типоразмеров (SMD, SOT, DPAK и др.) вне зависимости от категории компонента.
* **Fail-soft архитектура:** Модуль защищен от падений при встрече с неизвестными типами изделий, сохраняя их как «Обобщенные компоненты».

## 3. Описание логики парсинга (app/logic/bom_parser.py)

Модуль реализует функцию `parse_with_context`, которая выполняет следующие шаги:

### Шаг 1: Извлечение типоразмера (Package)
Используется универсальный Regex-паттерн для поиска стандартных корпусов электроники во всей строке.
*Примеры: `0603`, `SOT-23`, `LQFP-48`.*

### Шаг 2: Обработка по категориям
В зависимости от `category_context` (заголовка раздела), применяются специализированные регулярные выражения:

1.  **Конденсаторы:** Извлекает емкость (в Фарадах) и рабочее напряжение (V).
2.  **Резисторы:** Извлекает сопротивление (в Омах) и точность (%).
3.  **Полупроводники:** Для диодов и транзисторов ищет параметры напряжения и диэлектрические свойства.
4.  **Микросхемы:** Приоритет отдается сохранению целостности Part Number (MPN).

### Шаг 3: Глобальные параметры
Поиск параметров, общих для всех категорий, таких как допуск (`tolerance`) и тип материала (например, `X7R`, `NP0`).

## 4. Таблица соответствия параметров

| Параметр      | Поле в БД       | Базовая единица | Пример в строке | Результат |
|:--------------|:----------------|:----------------|:----------------|:----------|
| Сопротивление | `value_numeric` | Ом (Ohm)        | `10k`           | `10000.0` |
| Емкость       | `value_numeric` | Фарад (F)       | `100nF`         | `1e-07`   |
| Напряжение    | `voltage`       | Вольт (V)       | `50B`           | `50.0`    |
| Корпус        | `package`       | String          | `0805`          | `0805`    |

## 5. Пример работы парсера

**Входная строка:**
> `"Конденсатор керамический чип 0603 4.7мкФ 25V X5R"`
> *Контекст: "Конденсаторы"*

**Выходной объект:**
```json
{
  "category": "Capacitors",
  "package": "0603",
  "value_numeric": 0.0000047,
  "value_unit": "F",
  "voltage": 25.0,
  "tolerance": "X5R",
  "raw_text": "Конденсатор керамический чип 0603 4.7мкФ 25V X5R"
}
```
## 6. Примечания для разработчика
* Для добавления новых типов компонентов достаточно расширить блоки elif в функции parse_with_context.

* При парсинге числовых значений используется замена запятой на точку для корректной конвертации во float.

* Парсер является "чистой функцией" (pure function), не делает запросов в БД и может быть легко протестирован отдельно через Unit-тесты.
